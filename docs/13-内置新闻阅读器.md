# 内置新闻阅读器

## 改造任务

- [x] 新闻点击改为桌面内部阅读窗口，复用单个窗口；公司官网仍显式打开外部浏览器。
- [x] Windows 使用 Microsoft.Web.WebView2 SDK 和系统 Evergreen Runtime，不打包固定版浏览器；缺少运行时显示安装入口。
- [x] macOS 通过 Avalonia NativeControlHost 直接托管系统 WKWebView，无 Chromium、商业 WebView 控件或新增原生编译工具链。
- [x] 提供后退、前进、刷新、地址显示和手动“在浏览器打开”；加载失败显示中英文提示。
- [x] 限制导航及弹窗至不含凭据的 HTTP/HTTPS URL，弹窗在同一窗口打开；无原生 JavaScript 桥接。
- [x] 增加新闻入口/协议策略测试，并把真实原生浏览器检查纳入四个平台 CI 和 required 汇总检查。

## 体积与本地数据

浏览器按首次打开新闻时初始化。Windows 引用固定版本 SDK，复用安装在系统中的 Evergreen Runtime。当前未指定 RID 的开发输出中，WebView2 托管 DLL 与三个架构加载器合计约 1.4 MiB；正式发布体积以对应 RID 包为准。缺少系统运行时需要另行安装，其下载体积不包括在应用内。macOS 仅增加托管封装代码，WebKit 由系统提供。

Windows 的独立浏览器配置在当前数据目录的 `browser/webview2`，包括网站可能保存的 Cookie/缓存；关闭阅读窗口会释放控件。macOS 使用非持久化网站数据存储，窗口会话结束后不保留网页 Cookie/缓存。网站脚本仍由系统引擎执行以支持正常新闻站点，不能调用应用原生服务。网页请求直接访问新闻发布者，遵循系统网络/代理配置，不复用行情供应商的应用内代理设置。

网站付费墙、登录要求、地区限制和反机器人验证仍由原网站决定；“在浏览器打开”供用户主动选择。错误提示不代表绕过这些限制。原生 CI 使用本地 HTML 验证引擎行为，不等同于所有新闻站点实测。

## 桌面、CLI、MCP 适用性

此功能是桌面窗口交互，未新增业务数据操作。CLI 的新闻命令和 MCP `get_news` 继续提供同一应用服务的标题、来源、时间和原文链接；无需新增打开网页的 CLI 命令或 MCP 工具，不允许 MCP 隐式启动 GUI。WebView2 依赖仅存在于 Windows 桌面项目，不进入 CLI/MCP 发布包。原有全量操作覆盖和四平台原生包检查继续执行。

## 验证

```sh
# Linux 可编译两种封装，但不能在 Linux 上运行系统 WebView
source tools/env.sh
dotnet build src/Meili.Mac/Meili.Mac.csproj
dotnet build src/Meili.App/Meili.App.csproj -p:EnableWindowsTargeting=true
bash build/test-headless.sh

# 在 Windows 或 macOS 原生桌面会话执行
# Windows 必须已安装 Microsoft Edge WebView2 Evergreen Runtime
dotnet run --project tests/Meili.NewsBrowser.Smoke/Meili.NewsBrowser.Smoke.csproj -c Release
```

原生测试加载回环地址的 HTML，断言真实文档标题、前进/后退、刷新请求、非法协议拦截及 HTTP 404 错误提示。CI 的 `Native news reader` 在 Windows x64/ARM64、macOS Intel/Apple Silicon 执行；失败会阻止 `CLI and MCP required` 通过。
