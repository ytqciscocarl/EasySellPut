# 后台运行、性能与 CI 审查

## 使用与生命周期

底部状态栏的「后台运行」图标可立即隐藏主窗口。设置中的「关闭主窗口时 → 后台运行」控制关闭按钮的行为；默认退出行为保留。GUI 支持 `--background` 启动。macOS 从状态栏/Dock 恢复，Windows 从托盘恢复；托盘不可用时保留任务栏并最小化，避免窗口无法找回。明确退出仍结束进程、监控与资源。

这是桌面进程后台运行，并非系统服务、自启动或阻止电脑休眠。个人网页的会话、历史及页面实例保留；已有下载、用户主动发起的操作不因为隐藏窗口而强行中断。

## 发现与修复

| 原问题 | 已实施策略 | 验收 |
| --- | --- | --- |
| 隐藏窗口不会自然触发页面卸载，行情页和图表继续工作 | 隐藏/最小化时摘除展示树，恢复时重新挂载原页面和 ViewModel | 重复隐藏/恢复三轮，模型保持、图表会话释放并恢复 |
| 隐藏后仍每秒更新时钟、每五秒扫描 MCP 文件 | 停止 Shell 展示计时器；恢复即时更新 | 隐藏期间 MCP 扫描增量为零 |
| 无行情订阅仍有定时唤醒 | 唯一 QuotePump 在最后一个订阅移除后停止 | 手动触发迟到事件不能新增请求 |
| 被动托盘行情沿用前台频率 | 全部展示隐藏且无价格提醒时，盘中/盘前后最低 30 秒 | 时间策略测试覆盖盘中、休市、前台与提醒 |
| 无 IV 提醒仍保留周期计时器 | 仅启用 IV 规则时启动采样；删除最后规则即取消 | 无规则零采样；添加、移除、停止行为测试 |
| macOS 无条件禁止 App Nap | 仅启用价格或 IV 提醒时申请活动权限，关闭最后提醒时释放 | 原生应用构建与退出冒烟；不宣称实测耗电 |
| 网页后台继续进行历史轮询/渲染 | WKWebView 停止应用侧历史轮询并隐藏；WebView2 尝试原生 Suspend，恢复 Resume | 四种桌面架构原生浏览器冒烟验证暂停/恢复、会话与历史 |
| 不可见 loading/行情闪动仍活跃 | 卸载/隐藏停止不确定进度；自选页停用时停止闪动 | 页面回归与恢复检查 |

行情刷新仍由既有 QuoteHub/QuotePump 统一承担，没有增加第二套市场请求循环。价格提醒维持原来的盘中 5 秒、盘前后 10 秒、休市 60 秒策略；可见的置顶行情速览仍使用正常展示频率。只有后台被动行情从盘中每分钟最多 12 个调度机会降至 2 个；这是策略预算，不是网络请求实测百分比。

图表属于应用私有内容，可以停止并在恢复时重建渲染会话；个人网页不得为了节能销毁并重新加载。macOS 公开 WKWebView API 不保证冻结所有远程 JavaScript；WebView2 Suspend 也可能被浏览器拒绝，不能声称后台 CPU 为零。

## 性能取样及限制

`BackgroundLifecycleTests` 在真实 Avalonia/Skia 测试宿主中分别采集三个一秒 CPU 时间窗口，并输出 `background-profile.json`，同时检查私有图表会话、展示计时器、行情订阅与 MCP 扫描。一次 Linux 样本：前台 CPU 时间为 214.510 / 297.390 / 300.840 ms；隐藏并预热后为 130.502 / 36.091 / 5.371 ms；托管内存约 12.6 MB，工作集约 148.5 MB。

该数据包括测试宿主、JIT、GC 与采样噪声，不包含真实 macOS WKWebView 子进程，也不是独立发布版本的硬件功耗/FPS 基准。不能据此计算产品节能比例。自动验收采用资源生命周期及请求计数，不设不稳定 CPU 百分比门槛。后续硬件验收应分别测量四种桌面架构的主进程及浏览器子进程，覆盖启用提醒、置顶窗口、复杂个人网页和休眠恢复。

## CI 审查与补齐

- 发现 Windows CI 只指定少数测试类，改为运行完整 `Category!=Live` 离线桌面测试集，两种 Windows 架构均执行。共享 WPF 测试宿主禁止并行，避免全局应用状态相互污染。
- Windows 开启实际桌面截图目录，保留截图、JSON、TRX；无头回归新增保留性能 JSON。零测试执行视为错误。
- macOS 两种架构与 Windows 两种架构继续实际运行原生 WebView 和打包产物。初始安装、更新后启动均使用 `--background`，再验证恢复、图表渲染、重新隐藏及真正退出。
- CLI/MCP 全部 45 项能力继续通过真实双协议进程对照，关闭行为偏好增加 `MinimizeToTray` 的持久化对照断言。桌面展示生命周期是 UI 专属，不额外启动 CLI/MCP 守护进程。
- 继续保留五个平台/架构的自动化产物执行、默认只读 MCP 写权限检查、更新安装流程和稳定聚合检查 `CLI and MCP required`。

## 尚不能由当前 CI 保证的事项

检查时 GitHub 的 `main` 与 `work` 分支均未启用分支保护。因此有聚合检查并不代表失败时不能合并；建议为 main 设置必须通过 `CLI and MCP required`，此改动未擅自修改仓库治理配置。

离线 fixture 不证明真实行情源当前可用；现有 live CLI/MCP 检查需显式启用。CI 没有桌面硬件耗电、长期内存泄漏和真实交互 FPS 基准，也没有以覆盖率百分比作为门槛。测试覆盖的边界与原生运行结果应结合解读，不能把交叉编译当作原生运行。
