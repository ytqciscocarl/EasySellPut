# 沉浸式窗口标题栏

## 行为与组件

窗口上方采用与工作区一致的实时主题背景，36px 共享 WindowHeaderHeight，不显示应用名称，不再叠加系统灰色横条。标题栏不做位移、模糊或尺寸动画，避免拖窗和原生 WebView 呈现抖动。

Windows 继续使用 WPF-UI TitleBar 的系统命中测试与窗口动作，保留最小化、最大化、关闭、边缘缩放和系统菜单。背景、文字、按钮前景引用共享设计资源，运行中切换主题立即更新。

macOS 的 Avalonia 窗口请求扩展内容到装饰区，保留原生红黄绿按钮与窗口阴影；应用仅绘制统一背景与可拖动安全区，并在下方保留内容安全区。全屏移除应用标题带，保留系统全屏退出机制。

Linux 复用同一 Avalonia 标题带与框架窗口装饰，不关闭 WindowDecorations，也不手工模拟窗口按钮。支持客户端装饰时使用框架提供的拖动、缩放和窗口动作；窗口管理器拒绝扩展时隐藏应用标题带，回退系统标题栏，避免双层空白。不同 compositor 的窗口按钮位置与行为仍由系统/框架决定。

`DesignSystem/WindowChrome.axaml` 基于框架装饰主题，只调整背景和重复标题文字，不复制 caption 按钮模板。标题带声明 TitleBar 非客户区角色，内部文字不拦截拖动；页面与 WebView 不进入窗口按钮所在安全区。

应用的 Window.Title 仍保留，供系统窗口切换器、任务栏和辅助技术识别；只移除页面顶部的可见重复名称。

## 覆盖与验证

这是桌面窗口展示变化，不增加业务操作，CLI/MCP 契约和 45 项操作保持不变。

- Avalonia WindowChromeTests：两种主题、两种语言、980/1440 宽度的真实布局与渲染；隐藏重复标题、内容安全区、主题颜色、全屏/恢复及不支持扩展时的回退。
- WPF WindowChromeTests：真实窗口标题栏尺寸、主题、窗口控制可用和内容安全区，进入 Windows 全量回归。
- macOS 原生安装包自检：实际扩展状态、标题带高度与页面无重叠；由四架构桌面 CI 中两个 macOS 作业执行。Windows 保留其两个原生架构和 WebView/安装包自检。
- 本地截图在 `build/out/window-chrome`。Linux headless 截图是真实 Skia 组件渲染，为了展示应用标题带，测试显式开启它；没有绘制假的 macOS 红黄绿按钮，不能将其当作原生 macOS 截屏。

当前正式桌面发布矩阵仍是 Windows/macOS 四架构；Linux 的 CLI/MCP 已有原生 CI。Linux 具体桌面环境的系统装饰仍需 X11/Wayland 实机观察，本次不把 headless 证据宣称为各 Linux 窗口管理器已验收。
