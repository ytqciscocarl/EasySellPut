# Update reminders and footer indicator

## Behavior

- After production startup, wait 10 seconds of visible presentation before checking once. A hidden/minimized main window cancels the pending/inflight startup check. No recurring update poll is added.
- A successfully verified available release opens one owned, nonblocking reminder per version per process. The same version does not repeatedly interrupt after dismissal, rechecks or restore.
- **The footer indicator exists only while an available release is known.** Current/no-release/unverified states show no update indicator. Clicking it reopens the reminder without another request.
- “Later” or closing the reminder keeps the footer entry. Download and install remain explicit, separate actions. Download completion changes the entry to “ready”. Existing installer confirmation, signature verification, MCP preflight and rollback remain in force.
- When hidden, the reminder closes. A release first discovered while hidden may be offered on restore; already presented versions stay dismissed. Manual settings checks remain available after startup failure/cancellation.

## Ownership and reuse

`UpdateViewModel` is a desktop singleton shared by settings, footer and reminder. `SettingsViewModel.Updates` references it; the update client/coordinator and trust policy are unchanged. Both native `UpdateDialog` views derive from existing `AppDialog` and use the existing tokens, buttons, typography, progress and pinned Lucide Download/Close icons. Notes are plain text in a bounded scroll area.

No CLI/MCP capability is added: reminder visibility is UI-only, recorded in `desktop_capabilities.json`. Business operations and updater transport remain unchanged.

## Verification

- Shared regression covers once-per-version behavior, footer reopening, hidden deferral, no-release/current/signature failures, download-ready/localization and cancellation of a startup request.
- Avalonia and WPF UI tests exercise the actual footer/dialog bindings, Later, reopening, no implicit download/install, hide/restore, shared download state and collapsing after a current response.
- Existing installer safety and settings update-card cases continue to run. CI discovers all offline tests rather than maintaining a class allowlist. UI and Windows step labels mention update reminders; screenshots remain in existing UI/native artifacts.
- Main-window screenshots are rendered at 1920×1080. Dialog-only captures retain their natural size and are labeled separately; Windows CI also captures the real full desktop with the dialog.
- Existing official repository/key/signing setup requirements still apply. Fixture v0.7.0 images do not represent a published release.
